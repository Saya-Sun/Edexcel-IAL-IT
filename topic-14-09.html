System Maintenance

Understand why organisations maintain IT systems, how perfective, adaptive and corrective maintenance differ, and how regression testing protects existing functionality.

📚 Using IT Systems in Organisations📝 Detailed Lesson Notes
Lesson overview: Maintenance is an ongoing responsibility for all organisations. This lesson covers three maintenance types, their triggers and benefits, the corrective maintenance process, regression testing, and a worked solution to Textbook Activity 8.
🧩
Section 01

Introduction to System Maintenance

1.1 What is system maintenance?

📖 Key definition

System maintenance is the ongoing process of checking, managing, testing and updating an IT system to ensure that it continues to operate effectively, reliably and efficiently.

When an organisation develops or installs an IT system, its responsibility does not end when the system becomes operational. Over time, the system may experience problems, become less efficient or need modifications because business requirements change.

Organisations therefore maintain their systems to make sure they continue to carry out necessary tasks and support business goals.

💡 Example: Online education platform

A school uses an online platform where students log in, access lessons, complete assessments and view results. After several months, some students cannot log in, pages load slowly and the system needs to support a new browser. The school must maintain the platform to address these issues and keep it useful.

1.2 Why is maintenance important?

🛡️ Reliability

Keeps system functions operating consistently and correctly.

⚡ Performance

Helps the system respond quickly and use resources efficiently.

🏢 Business continuity

Reduces disruption to daily organisational operations.

😊 User satisfaction

Allows users to complete tasks without unnecessary difficulties.

🔗 Compatibility

Keeps systems working with changes in hardware and software.

📋 Compliance and goals

Helps meet legal requirements and organisational objectives.

Example: If a retailer's electronic point-of-sale (EPOS) system repeatedly fails, customers may be unable to purchase products. Maintenance can reduce disruptions and lost sales.

1.3 The three types of maintenance

✨ Perfective

Improve a system that already works.

🔄 Adaptive

Modify a system to accommodate external changes.

🛠️ Corrective

Identify and fix errors, bugs or defects.

✨
Section 02

Perfective Maintenance

2.1 What is perfective maintenance?

📖 Key definition

Perfective maintenance is the process of identifying and implementing improvements to an existing IT system that is already functioning correctly.

Its purpose is not to repair a broken system, but to make a working system better. It may increase efficiency, enhance performance, improve user experience or add functionality.

2.2 Why is perfective maintenance required?

💬 A. User feedback

Students request a search feature for lesson materials. The school adds the feature to make the platform easier to use.

🚀 B. Better performance

Database search results take eight seconds to appear. Developers optimise queries to reduce the response time.

📱 C. Market trends

An online retailer redesigns its functioning website to improve the shopping experience on mobile devices.

🎯 D. Organisational objectives

A school adds a dashboard showing attendance, assessment scores and course completion rates.

2.3 Examples of perfective maintenance

Existing system Improvement
School management system Add automatic student progress reports.
Online shopping website Improve product search and filtering.
Banking application Improve the transaction history layout.
Customer relationship management (CRM) system Add new sales performance charts.
Inventory management system Optimise database queries so reports are produced faster.

2.4 Benefits

  • Improved efficiency: users can complete tasks more quickly.
  • Better performance: the system responds faster and may use fewer resources.
  • Increased functionality: new features support more tasks.
  • Higher satisfaction: users gain a better experience.
  • Greater competitiveness: organisations can improve the services they offer.

2.5 Challenges

  • Development requires time and money.
  • Users may need training for new features.
  • Code changes can introduce unexpected errors.
  • Installing improvements may require temporary downtime.
  • Too many new features can make a system unnecessarily complicated.
⭐ Remember

Perfective maintenance focuses on improvement, not fixing a defect or responding to a new external compatibility requirement.

🔄
Section 03

Adaptive Maintenance

3.1 What is adaptive maintenance?

📖 Key definition

Adaptive maintenance is the process of modifying an existing IT system so that it can continue operating effectively when changes occur in its external environment.

External changes may involve hardware, software, operating systems, legal requirements or industry regulations. A system may be working correctly but still require changes because another technology or requirement has changed.

💡 Example

A company upgrades its operating system, but its accounting software is incompatible with the new version. Developers update the accounting software to work in the new environment. This is adaptive maintenance.

3.2 Why is adaptive maintenance required?

🖨️ A. Hardware changes

New barcode scanners use a different communication method. Developers update the inventory software to support them.

💻 B. Software changes

A new database management system no longer supports certain commands. Application code must be modified.

⚖️ C. Legal requirements

A change in data protection requirements means the organisation must update its data retention procedures.

📑 D. Industry regulations

A financial institution modifies its reporting system to produce information in a newly required format.

3.3 What parts of a system may change?

Component Explanation Example
Back-end processes Internal operations that process information and support the system. Update payment-processing procedures.
System code Instructions that control software behaviour. Change code to support a new operating system.
Configuration Settings that control system operation. Change database connection settings after migration.
System architecture Underlying structure and organisation of the system. Modify the application to run with new server infrastructure.

3.4 Example: Adapting an online education system

A school replaces its existing database software with a newer platform. Its education website can no longer communicate correctly with the database.

  1. Identify compatibility problems with the new database.
  2. Examine existing database connections and queries.
  3. Modify application code and configuration.
  4. Test the website with the replacement database.
  5. Deploy the changes once essential functions work correctly.

This is adaptive maintenance because the website is being changed to operate in a new technological environment.

3.5 Benefits

  • Maintains compatibility with new hardware and software.
  • Helps organisations meet new legal and regulatory requirements.
  • Keeps existing systems operational despite external changes.
  • May extend the useful life of systems.
  • Can reduce the need for complete system replacement.

3.6 Challenges

  • Compatibility changes can be technically difficult.
  • Specialist skills may be needed.
  • Architectural changes can be expensive.
  • Modifications may affect existing functions.
  • Thorough testing is needed before deployment.
⭐ Remember

Adaptive maintenance focuses on responding to external changes, such as new technology or amended regulations.

🛠️
Section 04

Corrective Maintenance

4.1 What is corrective maintenance?

📖 Key definition

Corrective maintenance is the process of identifying, investigating and fixing errors, bugs or defects in an IT system.

Corrective maintenance is usually reactive: it begins after a problem has been discovered. Users may report the problem, or monitoring tools may detect unexpected system behaviour.

4.2 What problems may require corrective maintenance?

🐞 A. Software bugs

A shopping website applies a discount incorrectly, causing the final price to be wrong.

⚠️ B. System errors

A student system displays an error whenever a teacher generates an attendance report.

🧮 C. Unexpected behaviour

A payroll system produces incorrect overtime calculations without showing an error message.

🔐 D. User-reported problems

Several students cannot log in even though their usernames and passwords are correct.

4.3 The corrective maintenance process

Developers should follow a systematic process rather than making changes without understanding the cause of the problem.

  1. Identify and record the problemCollect error reports, system logs, screenshots, the circumstances of the failure and the number of users affected.
  2. Investigate the root causeExamine relevant code, database queries, configuration and logs to find the underlying reason for the fault.
  3. Develop and apply a fixCorrect faulty code, queries, settings or components. Make the change in a controlled environment.
  4. Test the correctionCheck that the original error has been resolved, including the situation that caused the failure.
  5. Perform regression testingTest related and existing functions to ensure the correction has not caused new faults.
  6. Deploy and monitorRelease the tested correction and check that the system continues operating normally.

Step 1: Identify the problem

Useful information may include error messages, timestamps, affected accounts, system logs and steps to reproduce the fault. For example, only recently registered students may be unable to log in, while existing accounts work correctly.

Step 2: Investigate the root cause

The root cause is the underlying reason a problem occurs. A website may display “Incorrect password”, although the actual cause is faulty authentication code. Developers may inspect the login form, authentication logic, database queries, user records and server configuration.

Step 3: Implement the correction

Once the cause is identified, developers modify the relevant code or configuration. For example, they may correct an authentication query that checks the wrong database field.

Step 4: Test the correction

Developers verify that the previously failing function now works. In a login example, affected students should be able to sign in successfully, and invalid credentials should still be rejected.

Step 5: Perform regression testing

📖 Key definition

Regression testing is testing performed after a system is modified to ensure that the changes have not introduced new errors or adversely affected existing functionality.

Different system functions often share code or services. A correction to one part of a system can unintentionally affect another part.

💡 Why regression testing matters

A developer fixes a student login problem. Students can now log in, but an unintended change prevents teachers from signing in. Regression testing should detect this new problem before the update is released.

Regression test Expected result
Student enters valid credentials. Student logs in successfully.
Student enters an incorrect password. Login is rejected correctly.
Teacher enters valid credentials. Teacher logs in successfully.
User requests a password reset. Password reset works correctly.
User logs out. The session ends correctly.
Unauthenticated user opens a protected page. Access is denied.

Step 6: Deploy and monitor

After successful testing, the fix is deployed to the live system. Developers monitor error logs, check that affected users can complete tasks and document the solution for future reference.

4.4 Benefits

  • Restores failed or incorrect system functions.
  • Improves reliability and reduces disruption.
  • Helps maintain the accuracy of processed information.
  • Increases user confidence.
  • Stops known defects from repeatedly affecting users.

4.5 Challenges

  • Finding the root cause may take time.
  • Some defects occur only in unusual situations.
  • Fixing one component may affect other functions.
  • Critical errors can interrupt business operations.
  • Thorough testing is necessary before a fix is released.
⭐ Remember

Corrective maintenance focuses on fixing an identified problem. Following a change, regression testing checks that other parts of the system still work correctly.

Section 05

Comparing the Three Types

The reason for making a change is the best way to identify the maintenance type in a real-world scenario.

Feature Perfective Adaptive Corrective
Main purpose Improve a system. Accommodate external change. Fix a defect.
System condition Already working. May work but needs adaptation. Has an identified fault.
Typical trigger Feedback, performance goals, new features. New hardware, software, laws or regulations. Error reports or abnormal behaviour.
Typical action Optimise or add functionality. Modify code, settings or architecture. Diagnose and repair.
Example Add a reporting dashboard. Support a new operating system. Repair a login bug.

5.1 Recognising maintenance scenarios

Situation Maintenance type Why?
A school adds automatic report generation. Perfective A new feature improves the working system.
Accounting software is updated to work with a new operating system. Adaptive The software accommodates an external change.
Customers cannot log in and the developer repairs the error. Corrective An identified defect is fixed.
A retailer speeds up existing product pages. Perfective System performance is improved.
A database is updated to meet a new legal requirement. Adaptive The system responds to external regulations.

✨ Perfective

Make it better.

🔄 Adaptive

Make it compatible.

🛠️ Corrective

Make it work correctly again.

Section 06

Worked Example: Online Learning System

A school operates an online education platform that supports lessons, assessments, student registration and login accounts. Consider these three situations.

📊 Situation 1: Better dashboard

Teachers request a new dashboard showing student quiz results and progress.

Perfective: a functioning system gains extra features.

🗄️ Situation 2: Database upgrade

The school replaces its database, and developers update website connections to work with it.

Adaptive: the system accommodates new technology.

🔑 Situation 3: Login failure

Some students cannot sign in with valid credentials. Developers find and repair the defect.

Corrective: an identified error is repaired.

⭐ Important

After repairing the login issue, the school should carry out regression testing to confirm that other account functions still work correctly.

Section 07

Textbook Activity 8: Worked Solution

📚 Textbook scenario

A small group of website users report that they cannot log into the system using their usernames and passwords.

Question 1: What type of maintenance is needed to identify and rectify this problem?

Answer: Corrective maintenance. The website has an identified login fault preventing some users from accessing their accounts. The developer must investigate and correct the defect.

Question 2: Describe the processes the developer should follow to rectify the problem.
  1. Record the problem: collect error messages, affected account details and the circumstances of failed login attempts. Do not ask users to disclose passwords.
  2. Reproduce the fault: attempt the same login process in a controlled test environment.
  3. Find the root cause: check the authentication code, database queries, user records and system logs.
  4. Apply a correction: modify the faulty code or configuration responsible for the failed logins.
  5. Test the corrected function: verify that affected accounts can sign in and incorrect credentials are rejected.
  6. Perform regression testing: test teacher login, password reset, registration, logout and other related functions to ensure no new problems were introduced.
  7. Deploy and monitor: release the tested fix and check that users can log in reliably.

This is a complete, structured response showing both the type of maintenance and the importance of testing after the correction.

Section 08

Important Terms and Definitions

Term Definition
System maintenance Ongoing checking, managing and updating of IT systems to ensure their effectiveness.
Perfective maintenance Improving a working system to increase efficiency, performance or functionality.
Adaptive maintenance Modifying a system to accommodate changes in its external environment.
Corrective maintenance Identifying and repairing errors, bugs or defects.
Software bug An error or defect that causes a program to behave incorrectly.
Root cause The underlying reason why an identified problem occurs.
Reactive maintenance Maintenance performed in response to an identified issue.
Regression testing Testing after modification to check that existing functions still operate correctly.
System compatibility The ability of different hardware or software components to work together.
System configuration Settings that control how a system operates.
System architecture The underlying structure and organisation of an IT system.
✅
Section 09

Final Understanding

System maintenance continues throughout the operational life of an IT system. It allows organisations to keep their systems reliable, efficient and aligned with business goals.

The central difference between the three types of maintenance is why the change is needed:

Perfective

Improve a working system.

Adaptive

Respond to external change.

Corrective

Repair an identified fault.

For corrective maintenance, it is especially important to identify the root cause and perform regression testing after applying the fix, to check that previously working functions remain correct.

🎓 Main takeaway

All three maintenance types help an organisation ensure that its IT system continues to perform the tasks needed to meet its objectives.
