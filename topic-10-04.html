Section 01

Introduction to Web Accessibility

Websites are used by people with different abilities, ages, needs and levels of experience. Not everyone interacts with websites in the same way.

Some users may have difficulty seeing text, hearing audio, using a mouse or understanding complex instructions. Web designers must therefore consider these differences when building websites.

Key definition · Web accessibilityWeb accessibility means designing and developing websites so that people with different abilities, including people with disabilities, can access, understand, navigate and interact with website content and functions.
Example: A student with a visual impairment may use screen-reading software to hear the content of a lesson instead of reading it visually. A meaningful page structure and suitable text alternatives make the information easier for the screen reader to communicate.

1.1 Why is accessibility important?

Accessibility helps remove barriers that could prevent people from using a website successfully.

👥

Wider audience

More people can use the website, including those with disabilities or different access requirements.

🔓

Equal access to information

Users have a better opportunity to obtain information and complete activities independently.

✨

Improved user experience

Clear instructions, readable text and accessible navigation can make websites easier for everyone.

⌨️

Flexible access

Different devices, input methods and assistive technologies can be used.

Remember: People have different individual requirements. A successful web design should consider a wide variety of users, not only the typical user.

Section 02

Understanding Different Accessibility Needs

Accessibility requirements vary from person to person. The following categories help designers recognise possible barriers and choose suitable solutions.

👁️

2.1 Visual impairments

Some people have low vision, colour-vision deficiencies or no functional vision.

Solutions: image alternatives, adjustable text, sufficient contrast and screen-reader support.

👂

2.2 Hearing impairments

Some people are deaf or find it difficult to hear sounds clearly.

Solutions: subtitles, captions and transcripts for audio and video.

🖐️

2.3 Physical and motor impairments

Some people have difficulty using a mouse, making precise gestures or dragging objects.

Solutions: keyboard navigation, sufficiently sized controls and alternatives to complex mouse movements.

🧠

2.4 Cognitive and learning disabilities

Some people experience difficulties with attention, reading, memory or complicated instructions.

Solutions: clear language, consistent navigation, predictable layouts and easy-to-follow instructions.

🌙

2.5 Photosensitivity and sensory needs

Flashing content, some animations or excessive sensory stimulation can create problems.

Solutions: avoid hazardous flashing effects and allow motion to be paused or reduced when appropriate.

🌟

2.6 Accessibility benefits everyone

Captions help people in noisy places; larger text helps on small screens; keyboard navigation helps when a mouse is unavailable.

Situational accessibility: A student watching an educational video on a noisy bus may use captions even without a hearing impairment. Accessible features help people in permanent, temporary and situational circumstances.

Section 03

What Are the Web Content Accessibility Guidelines?

3.1 Definition of WCAG

Key definition · WCAGThe Web Content Accessibility Guidelines (WCAG) are internationally recognised recommendations for making web content more accessible, particularly to people with disabilities.

WCAG is developed through the World Wide Web Consortium (W3C) and its Web Accessibility Initiative (WAI). It gives designers and developers guidance on reducing barriers.

For example, WCAG addresses image text alternatives, video captions and the ability to use website functions with a keyboard.

3.2 Why are WCAG needed?

Without a shared set of guidelines, web developers may disagree about what makes a website accessible. WCAG supplies a structured framework for designing and evaluating websites consistently.

Example: Rather than assuming that a button is easy to use because it looks clear, a designer can test whether it works from the keyboard and whether users understand its purpose.

3.3 WCAG versions

W3C Recommendation

WCAG 2.2

The current W3C Recommendation described in the supplied lesson notes. It was first published in October 2023 and updated in December 2024.

Working draft

WCAG 3.0

Still being developed. The notes refer to a revised working draft dated 10 September 2026; it has not replaced WCAG 2.2.

For this course: The main aim is to understand and apply accessibility concepts required by syllabus 10.2.1 rather than memorise publication dates.

Section 04

The Four Main Principles of WCAG

WCAG 2 is organised around four fundamental principles. Their initials form the useful acronym POUR.

PPerceivable

Users can perceive information.

OOperable

Users can operate controls.

UUnderstandable

Users can understand content and actions.

RRobust

Content works with different technologies.

4.1 Perceivable

Information must be presented in ways that users can perceive. Someone who cannot see an informative image needs a suitable text alternative, and someone who cannot hear a video needs appropriate captions or alternatives.

4.2 Operable

Website functions must be usable through suitable input methods. A person who cannot use a mouse should be able to navigate links, buttons and forms using a keyboard.

4.3 Understandable

Information and operations should be clear and predictable. For example, a registration form should explain which details are required and show a helpful message when an entry is invalid.

4.4 Robust

Content should work with different technologies, including assistive technologies. Meaningful HTML structure and correctly implemented controls can help screen readers identify elements and explain what they do.

Remember POUR: Perceivable = notice the information; Operable = use the controls; Understandable = comprehend the content; Robust = work across technologies.

Section 06

Basic Examples of Accessible Website Design

The following examples show how accessibility principles can be applied when creating web pages.

6.1 Alternative text for images

Someone using a screen reader may not be able to obtain the meaning of an informative image without an alternative text description.

ACCESSIBLE HTML EXAMPLEAlternative text
<img
  src="laptop.jpg"
  alt="A laptop computer on a desk"
>

The alt attribute describes the meaningful content of the image. A screen reader can use it to communicate the image's meaning.

Important: Decorative images generally use empty alternative text (alt="") so screen readers do not announce descriptions that add no useful information.

6.2 Captions for videos

Imagine a video lesson explaining computer networks. If the explanation is only spoken, a student who cannot hear the audio may miss important information.

▶Computer Networks Lesson
“The router forwards data packets across the network.”

Illustration: captions communicate speech and relevant sounds in a video.

Providing captions allows users to read the spoken information and relevant sounds. Transcripts provide a text version of audio or video content.

6.3 Keyboard accessibility

A website should not require mouse-only actions. Common keyboard navigation controls include:

Key Common purpose
Tab Move focus to the next interactive element.
Shift + Tab Move focus to the previous interactive element.
Enter Activate a focused link or button.
Space Activate certain controls, including native HTML buttons.
Try it on this page: Press Tab to move between the lesson links and buttons. The focused control has a visible outline so its location is easier to identify.

Exact keyboard behaviour can depend on the type of element and the browser.

Section 07

Accessibility and Usability

Accessibility and usability are closely related, but they are not identical concepts.

♿ Accessibility

Focuses on whether people with different abilities can access and use a website.

🧭 Usability

Focuses on how easily and effectively users can complete tasks on a website.

Accessibility Usability
Supports users with differing abilities and access requirements. Helps people complete tasks efficiently and effectively.
Includes keyboard operation and screen-reader support. Includes intuitive navigation and logical page layouts.
Addresses barriers to accessing content and functions. Addresses confusion, inefficiency and unnecessary complexity.
Example: A navigation menu might look attractive and be easy to understand, but if it cannot be operated with a keyboard it is inaccessible to some users.

A website could also meet important technical accessibility requirements but still have a confusing layout. Good web design should be both accessible and usable.

Section 08

Applying Accessibility to an Online Learning Website

Consider a school website where students access lessons, watch instructional videos and complete activities. The following design decisions help students with different access needs.

Website feature Accessibility consideration
Lesson images Provide meaningful alternative text where needed.
Instructional videos Include appropriate captions and transcripts.
Navigation menu Support keyboard navigation and clearly labelled links.
Lesson text Use readable fonts, suitable sizes and sufficient contrast.
Timed activities Provide suitable time adjustments where required.
Registration forms Provide labels, instructions and helpful error messages.
Mobile layout Adapt content to different screen sizes and orientations.

Example: Completing a lesson online

Student using a keyboard

Can travel from the topic dashboard to a lesson and activate relevant controls without a mouse.

Student unable to hear video audio

Can obtain equivalent information through captions, transcripts or other appropriate text alternatives.

Design principle: Accessibility should be considered throughout website planning, design and development, rather than being added only when the website is finished.

Section 09

Common Misunderstandings

These common misconceptions can lead to websites that appear accessible but still prevent some people from using them.

✕
“Accessibility only helps people with disabilities.”

Captions, flexible text and keyboard support also help users facing temporary or situational difficulties.

✕
“An attractive website is automatically accessible.”

It may still contain low-contrast text, inaccessible navigation or videos without captions.

✕
“Accessibility is only about visual impairments.”

Accessibility also covers auditory, physical, cognitive and other user needs.

✕
“A mobile-friendly website must be accessible.”

Responsive layout alone does not guarantee keyboard navigation, meaningful text alternatives or sufficient contrast.

✕
“Following one WCAG guideline makes the whole website accessible.”

Accessibility requires attention to multiple areas; image alternative text alone is not enough.

🏁
Section 10

Conclusion

Web accessibility matters because people have different abilities, needs and ways of interacting with technology. The Web Content Accessibility Guidelines provide a structured approach to reducing barriers.

WCAG 2 is organised around the four principles of Perceivable, Operable, Understandable and Robust (POUR). These principles help designers make sure that users can perceive information, operate functions, understand content and use websites with different technologies.

Accessibility includes everyone

It supports people with different permanent, temporary and situational access needs.

WCAG provides guidance

The textbook introduces 13 guideline areas across the four POUR principles.

Accessibility and usability complement each other

A site should be possible to use and straightforward to operate.

Design from the beginning

Consider accessibility throughout the development of a website.
