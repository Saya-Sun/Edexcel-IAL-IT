Managing an IT Project

Learn how a project manager organises complex activities, allocates resources, manages risks, maintains quality, controls changes and keeps an IT project on schedule.

📚 7 Learning Areas 🎓 A2 Level 💻 Systems Development

📖 Introduction

A project manager is responsible for ensuring that an IT project is planned, organised, monitored and completed effectively.

Successful project management involves managing tasks, people, equipment, money, time, changes and potential problems.

There are seven important aspects of managing an IT project. Each aspect helps the project manager achieve the agreed objectives while controlling time, cost and quality.

🧩
SECTION 2.1

Complexity Management

Definition

Complexity management involves breaking a large, complicated project into smaller, manageable tasks.

Large IT projects may contain hundreds of activities involving different people, technologies and resources.

Some tasks depend on the completion of other tasks, while certain activities can be carried out at the same time.

Why is Complexity Management Important?

👥

Clear Responsibilities

Each task can be assigned to a suitable individual or team.

⏱️

Time Estimation

The project manager can estimate how long individual activities will take.

📊

Progress Monitoring

Completed and unfinished tasks can be identified more easily.

🔍

Problem Identification

Missing tasks, delays and dependencies can be detected more easily.

Example: E-commerce Website Development

Consider a company developing an online shopping website. Its activities include:

1

Design the database structure.

↓
2

Create the database.

↓
3

Connect the website to the database.

↓
4

Test the complete system.

↓
5

Deploy the website.

These activities have dependencies. For example, the database needs to be created before the website can be connected to it.

However, some tasks, such as designing the user interface and preparing database structures, may be carried out in parallel.

💡 Practical Example

Instead of assigning one team to "Develop the entire website", the project manager divides the work into smaller activities:

  • User interface design
  • Database development
  • Payment integration
  • System testing

This makes responsibilities clearer and helps prevent important work from being overlooked.

💡

Key idea: Breaking a complicated project into manageable tasks makes it easier to plan, organise, assign responsibilities and track progress.

👥
SECTION 2.2

Resource Allocation

Definition

Resource allocation is the process of assigning the resources needed to complete different project activities effectively.

A project manager must ensure that suitable resources are available for each task, without wasting resources or assigning too much work to one resource.

Types of Project Resources

Resource Type Examples
Human Resources Programmers, database administrators, network engineers and testers.
Physical Resources Computers, servers, networking equipment and storage devices.
Software Resources Development tools, testing software and software licences.
Financial Resources Budget for salaries, equipment, services and other costs.
Time Resources Available working hours and project deadlines.

Resource Overallocation

Resource overallocation occurs when a resource has been assigned more work than it can reasonably complete during the available time.

💡 Example: Company Network Upgrade

A company is upgrading its network.

  • A network engineer is responsible for configuring a server.
  • A technician is responsible for installing Ethernet cabling.

If both activities require the same engineer at exactly the same time, a resource conflict may occur.

The project manager can resolve the conflict by assigning another qualified person or rescheduling one activity.

Benefits of Effective Resource Allocation

✅

Fewer Delays

Required resources are available when tasks need them.

💰

Lower Waste

Resources are used efficiently to help control project costs.

⚖️

Balanced Workload

Staff are less likely to become overworked or underused.

📈

Higher Productivity

People and equipment can be used more effectively.

💡

Key idea: Appropriate resource allocation helps prevent delays, reduce waste and control project costs.

🛡️
SECTION 2.3

Risk Mitigation

Risk

A risk is a possible event or situation that could negatively affect the success of a project.

Risk Mitigation

Risk mitigation involves identifying possible risks and taking action to reduce their likelihood or impact.

Four Categories of Project Risks

Risk Category Explanation Example
Changing Requirements Requirements are modified during development. A client requests additional features.
Technical Issues and Threats Problems involving hardware, software or security. Server failure or a data breach.
Human Factors Problems involving staff, mistakes or human behaviour. Developer absence or accidental deletion of data.
Wider Issues External events outside the project manager's direct control. Political instability, legislative changes or a pandemic.

Mitigation Plan vs Contingency Plan

🛡️ Mitigation Plan

Actions taken to reduce the probability of a risk occurring or to minimise its possible impact.

Example: Regularly backing up important data.

🚨 Contingency Plan

Actions prepared in case the risk actually occurs.

Example: Restoring lost data from a verified backup.

💡 Example: Hospital Patient Record System

A hospital is introducing a new electronic patient record system.

Possible risk: Important patient information may be lost during data migration.

Mitigation measures:

  • Create backups of existing data.
  • Test the data migration process.
  • Verify that data has been transferred accurately.

Contingency action: If the migration fails, restore the data from a verified backup and follow the recovery plan.

💡

Remember: Mitigation reduces the chance or impact of a problem. Contingency planning prepares a response if that problem occurs.

✅
SECTION 2.4

Quality Assurance (QA)

Definition

Quality assurance is the process of ensuring that appropriate procedures and standards are followed throughout a project so the final system meets agreed quality requirements.

Quality assurance is not limited to checking the system after development. It should occur throughout the entire project lifecycle.

Quality Assurance Activities

💻

Coding Standards

Ensure programmers follow agreed coding rules and conventions.

📐

Design Reviews

Review system designs to ensure they meet project requirements.

🔎

Regular Quality Reviews

Check whether procedures and quality standards are being followed.

📋

Requirements Checking

Ensure the development process continues to follow agreed requirements.

Quality assurance also includes ensuring that appropriate testing procedures are planned and followed.

💡 Example: Online Payment System

A company is developing an online payment system.

All developers are required to follow agreed security and coding standards.

The project manager checks that developers follow these quality procedures throughout development.

This reduces the likelihood of defects and helps ensure the final system meets the customer's requirements.

Important Distinction

Quality assurance focuses on following and improving processes to prevent defects.

Quality control focuses on checking the product to identify defects and verify that requirements are met.

💬
SECTION 2.5

Communication and Collaboration

💬 Communication

Sharing project information effectively with team members and stakeholders.

🤝 Collaboration

People working together to achieve common project objectives.

Most IT projects involve developers, designers, testers, managers, customers and other stakeholders.

The project manager must ensure everyone understands their responsibilities, deadlines, requirements and current progress.

Information That Must Be Communicated

  • Individual responsibilities
  • Project deadlines
  • System requirements
  • Current project progress
  • Problems and potential delays
  • Approved project changes

Communication Methods

👥

Team Meetings

Discuss progress, responsibilities and problems.

📊

Progress Reports

Provide updates about completed tasks and remaining work.

🗣️

Client Meetings

Confirm requirements and gather customer feedback.

🖥️

Project Management Software

Track tasks, assignments, deadlines and project progress.

💡 Example: Login Page Development

A designer changes the layout of a website's login page.

However, the designer does not inform the developer about the change.

The developer continues programming the original design.

As a result, some work must be repeated, wasting time and resources.

Solution: Regular communication ensures that everyone works with the latest approved information.

💡

Key idea: Effective communication reduces misunderstandings, prevents duplicated work and improves teamwork.

🔄
SECTION 2.6

Change Management

Definition

Change management is the process of assessing, planning and managing changes to project requirements or the organisation while minimising disruption.

Changes may be necessary because of:

🏢 New Business Needs 💻 New Technologies 👤 Customer Requests 📈 Market Conditions

Change Management Process

1

Change Request: A change is proposed.

↓
2

Impact Assessment: Assess effects on time, cost, resources and project scope.

↓
3

Decision: Approve, reject or negotiate the proposed change.

↓
4

Update Plans: Update project plans and inform relevant stakeholders of approved changes.

Feature Creep (Scope Creep)

Feature Creep

Feature creep occurs when additional features are introduced during development, potentially increasing the work required beyond the original project scope.

Feature creep is a type of scope creep. Scope creep refers more generally to uncontrolled expansion of the agreed project work.

💡 Example: School Attendance System

A school commissions a simple attendance management system.

During development, it requests additional features:

  • Online payment system
  • Online examination system
  • Student messaging system

Each feature requires additional development, testing, resources and time.

If these changes are not controlled, the project could experience significant delays and increased costs.

Important

Changes are not always negative. Proper change management allows useful changes while controlling their effects on project objectives.

📅
SECTION 2.7

Scheduling and Deadlines

Scheduling

Scheduling is the process of deciding when project tasks should start and finish, how long they should take and in what order they should be completed.

Deadline

A deadline is the latest agreed time or date by which a task or project must be completed.

Importance of Effective Scheduling

🔗

Task Dependencies

Identify tasks that must be completed before others can begin.

👥

Resource Planning

Allocate suitable people and resources at appropriate times.

📈

Progress Monitoring

Compare actual progress with the planned schedule.

⚠️

Delay Detection

Detect delays early so corrective action can be taken.

Time to Market

Definition

Time to market is the time required to develop a product and make it available for use or sale.

Reducing time to market may give an organisation a competitive advantage because it can introduce products before its competitors.

💡 Example: Mobile Application

Two companies are developing similar mobile applications.

Company A completes its development earlier and releases its product first.

Company A may attract customers and establish its product in the market before Company B.

Therefore, shorter time to market can create a competitive advantage.

⚠️ Important Consideration

Rushing development to release a product earlier may reduce the quality and reliability of the system.

Project managers must balance time, cost and quality.

💡

Key idea: Effective scheduling helps teams complete activities in the correct order, use resources efficiently and meet agreed deadlines.
