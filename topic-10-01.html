How to Design Web Pages

Understand how designers plan effective web pages using wireframes, mock-ups, web-design style guides and interactive prototypes.

📘 10 Learning Sections🎓 AS Level · Unit 2🎨 Principles of Design

Section 01

Introduction to Web Page Design

Before developers start writing HTML, CSS and JavaScript, they plan how a website should look, how its content should be organised and how users should interact with it.

KEY DEFINITION · WEB PAGE DESIGN

Web page design is the process of planning the structure, layout, appearance and interactions of a web page before it is fully developed.

A well-designed website should be easy to navigate, visually attractive, consistent and suitable for its intended users. For an online learning website, designers must decide where to place the navigation menu, lesson content, images and buttons.

The four main design tools

Section 02

Wireframes

2.1 What is a wireframe?

KEY DEFINITION · WIREFRAME

A wireframe is a simple, two-dimensional representation of a web page showing the arrangement and positioning of its main elements.

Think of a wireframe as an architect's blueprint. It concentrates on structure and layout, rather than the final colours, font choices or images.

A wireframe may show the position of the:

🏷️

Header and logo

Identifies the website at the top of the page.

☰

Navigation menu

Shows where users will find links to different pages.

📄

Main content, text and images

Reserves space for important information and visuals.

🧱

Sidebar and footer

Indicates supporting links and bottom-of-page information.

2.2 Example of a wireframe

2.3 Why are wireframes useful?

  1. Plan where information will appear.
  2. Decide how much space different page elements require.
  3. Organise content into a logical structure.
  4. Identify layout problems before development begins.
  5. Discuss suggested changes with clients and stakeholders.
💡 PRACTICAL EXAMPLE

A school requests a website. The designer uses a wireframe to show where the lessons, announcements and student login page will be located. The school can recommend changes before any code is written.

⚠️ Limitation: A wireframe does not communicate the finished page's visual appearance. Stakeholders may find it difficult to judge whether the final website will look attractive.
🖼️
Section 03

Mock-ups

3.1 What is a mock-up?

KEY DEFINITION · MOCK-UP

A mock-up is a more realistic visual representation of what the completed web page is expected to look like.

Unlike a wireframe, a mock-up includes the design decisions that make the page look closer to the real finished website:

🔠

Text and typography

Actual or representative wording, font sizes and styles.

🌈

Colours and backgrounds

The planned colour scheme and visual contrast.

📷

Images and logos

Proposed image choices and brand elements.

🔘

Buttons, icons and spacing

How interface controls and content will be aligned.

3.2 Example of a mock-up

3.3 Why create a mock-up?

A mock-up helps designers and stakeholders evaluate the appearance of the page before development. For example, a teacher could assess whether a purple header, dark sidebar and white lesson cards are appropriate.

  • Do the colours work well together?
  • Are headings readable and easy to recognise?
  • Is navigation clearly visible?
  • Are images suitable for students?
  • Does the design look consistent across the page?
Advantages Limitations
Shows a realistic representation of the final appearance. Usually does not demonstrate functionality.
Helps stakeholders provide feedback on the visual design. Takes more time to produce than a basic wireframe.
Helps identify visual problems and communicate intended styling. Redesigns may take time; it does not prove the page works.
🔍 Wireframe versus mock-up: A wireframe shows where elements will go. A mock-up shows what they will look like. A wireframe might label a rectangle “Login Button”; a mock-up could show the finished purple button with white text and rounded corners.
🎨
Section 04

Web-Design Style Guide

4.1 What is a style guide?

KEY DEFINITION · STYLE GUIDE

A web-design style guide is a document that specifies the formatting rules and visual standards that should be followed when creating pages for a website.

Its main purpose is consistency. For example, every page of a school's website should use the same logo, colour scheme, main heading style and navigation design.

4.2 What belongs in a style guide?

🔠

Text hierarchy

Headings, subheadings, paragraph text and how bold or italic text should be used.

🅰️

Fonts

Font families, sizes and colours for different levels of text.

📋

Tables and lists

Rules for borders, spacing, bullets and numbered lists.

🧩

Interface elements

Buttons, icons and guidelines for displaying images.

4.4 Why is a style guide important?

✅

Consistency

All pages look related and professional.

⚡

Efficiency

Developers do not have to select colours and fonts afresh for every page.

🤝

Team collaboration

Different developers can follow the same visual standards.

🔧

Maintenance

New pages can be added while preserving the website's visual identity.

💡 PRACTICAL EXAMPLE

If a school adds five new subject pages, a different developer can follow the existing style guide. The new pages will use the same colour palette, heading styles and buttons as the original website.

Section 05

Prototyping

5.1 What is a prototype?

KEY DEFINITION · PROTOTYPE

A prototype is an early digital model of a website that allows designers and users to explore how the website will function before the final version is developed.

A prototype is like a first working draft. Its key difference from a static mock-up is that a prototype can demonstrate interaction, such as a navigation button taking the user to another sample screen.

5.3 Why are prototypes useful?

  1. Demonstrate how website navigation will work.
  2. Allow users to test interactions and complete sample tasks.
  3. Collect feedback about the design.
  4. Identify usability problems early.
  5. Improve the design before full development.
  6. Reduce the risk of wasting time and money on unsuitable designs.
💡 PRACTICAL EXAMPLE

Students test a prototype of an online learning website and report that the lesson menu is difficult to locate. The developer can move the menu or make it clearer before building the final site.

5.4 Advantages and limitations

Advantages Limitations
Allows early testing of interactive features. May not include all final website features.
Helps identify usability problems. Creating it may require additional development time.
Encourages stakeholder feedback. Some interactions may only be simulated.
May prevent more expensive changes later. Users may mistake the prototype for a complete website.
⚖️

Comparison of the Four Design Tools

Each design tool serves a different purpose. Knowing these distinctions helps you choose the right tool for a particular design task.

Shows colours and fonts Usually no Yes Specifies rules Often yes

Useful for feedback Yes Yes Yes Yes

Section 07

How the Design Tools Work Together

The tools complement one another throughout website development. A possible workflow is:

01
Website requirements

Identify the users, the content they need and the features the website should provide.

02
Wireframe

Plan the structure, positioning and general layout of the page.

03
Mock-up and style guide

Choose the visual appearance and establish consistent formatting rules.

04
Prototype

Demonstrate navigation and let stakeholders try important interactions.

05
Feedback and improvements

Update the design to address problems before full development.

📌 Important: This is an example workflow, not a compulsory sequence. Designers may move between stages or revisit earlier decisions as requirements change.
🛒
Section 08

Real-World Application

Imagine a company is planning to build an online shopping website. Each design tool can help with a different part of the work.

Design tool Practical application
📐 Wireframe Plan where product images, search tools, categories and the shopping cart will appear.
🖼️ Mock-up Show product images, select fonts and colours, and illustrate the appearance of the Buy button.
🎨 Style guide Define a consistent appearance for product, checkout and navigation pages.
🖱️ Prototype Let users simulate finding a product, adding it to the basket and proceeding to checkout.
✅ WHY THIS MATTERS

These tools give the company an opportunity to discover layout, appearance and usability problems before investing in the complete working website.

Section 09

Common Misunderstandings

📐

Wireframe ≠ finished design

A wireframe mainly communicates structure and layout; it does not show the final colours and fonts.

🖼️

Mock-up ≠ working page

A mock-up may show buttons and menus without allowing a user to click them.

🎨

Style guide ≠ individual web page

A style guide contains design rules applied across many pages, not one complete page layout.

🖱️

Prototype ≠ finished website

A prototype may include only selected features needed to demonstrate and test interactions.

🔎 Remember: A prototype can simulate some features without having a real database, account system or checkout process. Its purpose is to explore and test the user experience.
🏁
Section 10

Conclusion

The four main design tools help developers plan and evaluate websites before full implementation.

📐

Wireframes

Establish the structure and layout.

🖼️

Mock-ups

Communicate the intended visual appearance.

🎨

Style guides

Maintain consistency across all pages.

🖱️

Prototypes

Allow interaction testing and feedback.

Together, they make it easier to meet user requirements, improve usability and reduce the risk of costly design changes later.
