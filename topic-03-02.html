Static and Dynamic Web Pages

Explore how static and dynamic websites deliver content, how scripting works, and how browsers and servers cooperate to create interactive web applications.

📚 10 Learning Areas 🎓 AS Level 🌐 The Online Environment

📖 Introduction

Websites provide information and services to users. Some web pages display the same information to everyone, while others change depending on the user, database records or other factors.

These are called static web pages and dynamic web pages. Understanding their differences helps developers choose suitable technologies for different website requirements.

📄
Section 1

Static Web Pages

1.1 What is a Static Web Page?

The word static means something that remains the same. A static web page contains content stored in files that are normally delivered without being generated separately for each visitor.

Key Definition

A static web page is a web page whose content is stored in a fixed form and normally delivered to users without being generated or modified by the web server for each request.

💡 Real-Life Example

School Information Page

A school website might show its address, opening hours, contact information, school rules and general course information. These details are normally the same for every visitor.

1.4 Characteristics

  • Content is normally stored in fixed files.
  • Basic pages do not require a database.
  • Server processing is generally minimal.
  • Content changes usually require editing or rebuilding files.
  • Suitable for relatively stable information.

1.5 Benefits

💰

🚀

💾

1.6 Limitations

Limited personalisationStored page files are normally the same for all users.
Repeated informationShared information may need updating in several files.
Advanced functionalityAccount histories and transactions need additional services or processing.
Important: Static does not mean non-interactive. A static page can still contain JavaScript-powered menus, buttons and animations.

Section 2

Dynamic Web Pages

2.1 What is a Dynamic Web Page?

Key Definition

A dynamic web page is a web page whose content can be generated or changed according to user information, database records, requests or changing data.

Dynamic web pages can show different information to different users or display information that changes over time.

💡 Example

Student Dashboard

An online learning platform may display each student's name, enrolled courses, completed lessons, assessment scores and teacher feedback.

The information varies because each student has different records.

  • Content may change according to user or database information.
  • Can provide personalised pages and services.
  • Often uses databases.
  • May use server-side code to generate responses.
  • Supports accounts, searches and transactions.

Section 4

Introduction to Scripting

Key Definition

Scripting is the use of instructions written in a scripting language to perform tasks, automate processes or control website behaviour.

4.1 Uses of Scripting

  • Responding to button clicks.
  • Validating form information.
  • Showing or hiding content.
  • Calculating values.
  • Retrieving information from databases.
  • Generating personalised pages.
  • Processing login requests.

4.2 Main Types of Scripting

🖥️

Client-Side Scripting

Scripts run on the user's device, normally inside the browser.

🗄️

Server-Side Scripting

Scripts run on a server to process requests and prepare responses.

Key difference: The execution location determines whether a script is client-side or server-side.
🖱️
Section 5

Client-Side Scripting

Key Definition

Client-side scripting means executing scripts on the user's device, normally in a web browser.

JavaScript is the most common client-side scripting language. It can update the interface and respond to user actions without requiring a newly generated page for every interaction.

5.1 How Client-Side Scripting Works

  1. The browser requests a web page.
  2. The server sends HTML, CSS and JavaScript files.
  3. The browser loads the page and executes JavaScript.
  4. JavaScript responds to user actions.
  5. The displayed page can change immediately.

5.2 Interactive Button Example

Click the button to display a message.

<button onclick="showMessage()">Click Me</button>
<p id="message"></p>

<script>
function showMessage() {
  document.getElementById("message").textContent =
    "Welcome to Tr.Sun Education!";
}
</script>

5.3 Benefits

⚡

Fast Response

Many actions can be handled immediately in the browser.

🖥️

Reduced Server Work

Simple calculations and visual changes can be handled locally.

🎮

Better Interactivity

Supports dropdown menus, animations and interactive forms.

📝

Immediate Feedback

Can check fields before a form is submitted.

5.4 Limitations

  • Downloaded JavaScript can be inspected by users.
  • Client-side checks cannot enforce security by themselves.
  • Browser differences may affect some features.
  • Complex scripts can use significant device resources.
  • Some functionality may fail if JavaScript is disabled.

5.5 Form Validation Example

Important: A real application must also validate information on the server. Client-side validation is useful for convenience, not sufficient security.
🗄️
Section 6

Server-Side Scripting

Key Definition

Server-side scripting is the execution of application code on a web server rather than in the user's browser.

The server processes requests and returns results. Common server-side technologies include PHP, Python, JavaScript with Node.js and ASP.NET.

6.1 How Server-Side Scripting Works

  1. The user sends a request, such as a login submission.
  2. The browser sends the request to the server.
  3. The server executes the appropriate application code.
  4. The application may access a database.
  5. The server prepares a response.
  6. The response is returned to the browser.

6.2 Example: Student Login System

💡 Real-Life Example

Online Classroom Login

  1. The student enters a username and password.
  2. The browser submits the information securely.
  3. The server finds the student's account.
  4. The password is checked against a stored password hash.
  5. The server verifies the student's permissions.
  6. An authenticated session is created if verification succeeds.

6.3 PHP Example

<?php
  $studentName = "Alice";
  echo "Welcome, " . $studentName;
?>

The generated output is:

Welcome, Alice

The browser receives the result, not the original server-side PHP code.

6.4 Benefits

🗃️

Database Access

Retrieves and updates records using authorised connections.

👤

Personalisation

Can generate information for individual users.

🔐

Code Confidentiality

Server-side source code is not normally delivered to users.

⚙️

Centralised Processing

Enforces application rules and permissions on the server.

6.5 Limitations

  • Server processing can increase resource requirements.
  • Network communication is required for server operations.
  • Database queries may cause delays.
  • Server applications require maintenance and updates.
  • Poorly written code can introduce security vulnerabilities.

Section 9

AJAX and Dynamic Content Updates

9.1 What is AJAX?

Key Definition

AJAX stands for Asynchronous JavaScript and XML. It is a technique that allows a browser to exchange data with a server in the background without reloading the entire web page.

Despite its name, modern AJAX applications commonly exchange data using JSON rather than XML.

9.2 How AJAX Works

  1. A user performs an action, such as typing in a search box.
  2. JavaScript sends a background request to the server.
  3. The server processes the request and returns data.
  4. JavaScript receives the response.
  5. The relevant part of the page updates without a full reload.

9.3 Live Search Example

Many websites provide suggestions while a user types. AJAX can retrieve matching records from a server and update the displayed suggestions.

Demonstration: This example filters a local JavaScript list. It works offline and does not send an AJAX request. A real AJAX search can retrieve records from a server.

9.4 Benefits of AJAX

⚡

Responsive Interaction

Selected content can update without reloading the page.

📡

Efficient Data Transfer

Only necessary information may need to be requested.

🔄

Background Updates

Data can be retrieved while users continue interacting.

😊

Improved Experience

Useful for live search, notifications and updated results.

10.1 Choosing the Appropriate Approach

📄

Choose Static Pages When...

  • Information changes infrequently.
  • The website is relatively simple.
  • Low hosting costs are important.
  • Server-generated personalisation is unnecessary.
🔄

Choose Dynamic Pages When...

  • Information changes frequently.
  • Users require personalised content.
  • Database records must be updated.
  • The application manages accounts or transactions.
💡 Final Concept

A modern website may combine static files, dynamic content, client-side JavaScript, server-side applications, databases and AJAX to provide a fast, interactive and secure experience.
